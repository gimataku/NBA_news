[YEL-01] ANTHROPIC_API_KEY / BALLDONTLIE_API_KEY が空でも起動時エラーにならない

  対象ファイル: config.py L7-8

  現状:
    ANTHROPIC_API_KEY   = os.getenv("ANTHROPIC_API_KEY", "")  # 空文字でも通過
    BALLDONTLIE_API_KEY = os.getenv("BALLDONTLIE_API_KEY", "")

  SECRET_KEY / USERNAME / USER_PASSWORD はRuntimeErrorで起動バリデーションが
  あるが（L61-74）、この2件は空文字のまま起動する。
  結果として「デプロイ成功→バッチ実行→初めてエラー発覚」という遅延障害になる。
  Renderの環境変数設定ミスを本番バッチ実行まで検出できない。

  修正案:
    if not ANTHROPIC_API_KEY:
        raise RuntimeError("ANTHROPIC_API_KEY が未設定です。")
    if not BALLDONTLIE_API_KEY:
        raise RuntimeError("BALLDONTLIE_API_KEY が未設定です。")

[YEL-02] /api/auth/login にレートリミットがない

  対象ファイル: api/routes.py L42-51

  detail_design_p2_v0.4.md に「ブルートフォース対策なし（設計判断・リスク受け入れ
  記録済み）」とあり既知の受け入れリスクだが、実際のコードを見ると制限が一切ない
  ことを改めて確認した。

  Render Starter は1インスタンスであり、高頻度の総当たり攻撃を受けた場合に
  レスポンス遅延が生じる可能性がある（DoS相当）。著作権法上の私的利用範囲でのみ
  公開するという前提でリスクは低いが、運用後に公開URLが漏洩するケースを想定すると
  最低限のIP別制限は将来的に検討余地がある。

  対処案（将来的に）: slowapi（FastAPI向けrate limiter）を導入し、
  /api/auth/login を「同一IPから10回/分」程度に制限する。
  今フェーズでは設計どおりのリスク受け入れで問題なし（再確認・記録目的で掲載）。

[YEL-03] /api/schedule の start_date / end_date に形式バリデーションがない

  対象ファイル: api/routes.py L82-90

  現状:
    async def get_schedule(start_date: str, end_date: str, ...):
        games = crud.get_game_schedule(start_date, end_date)

  SQLAlchemy ORMのパラメータバインドによりSQLインジェクションは起きないが、
  任意の文字列がそのまま文字列比較される（game_date >= start_date）。
  "2099-99-99" や "" を渡すと意図しない全件取得になりえる。
  認証済みユーザーのみアクセス可能なため実害は小さいが、防御的実装として
  形式チェックを追加すべき。

  修正案:
    from datetime import date

    def _parse_date(s: str) -> date:
        try:
            return date.fromisoformat(s)
        except ValueError:
            raise HTTPException(status_code=422, detail="日付はYYYY-MM-DD形式で指定してください")

    @router.get("/schedule")
    async def get_schedule(start_date: str, end_date: str, ...):
        _parse_date(start_date)
        _parse_date(end_date)
        ...

[YEL-04] render.yaml にPython/Nodeバージョンが未指定

  対象ファイル: render.yaml L3（env: python）、L38（env: static）

  現状、Pythonバージョン・Nodeバージョンのいずれも明示されていない。
  Renderはデフォルトのバージョンを使用するが、デフォルト値はRenderの更新に
  追随するため、将来のデプロイで突然Python 3.12+に上がりライブラリの
  非互換が発生するリスクがある（特にjwt.py L11: datetime.utcnow() は3.12で非推奨）。

  修正案（render.yaml に追記）:
    # バックエンド
    - type: web
      env: python
      runtime: python-3.11     ← 追加
      ...

    # フロントエンド（Node version）
    # .nvmrc / .node-version ファイルをリポジトリルートに配置するか、
    # Renderダッシュボードの環境変数で NODE_VERSION=20 を指定する

[GRN-01] jwt.py で datetime.utcnow() を使用している（Python 3.12+ で非推奨）

  対象ファイル: auth/jwt.py L11

  Python 3.12 から datetime.utcnow() はDeprecationWarningが出る。
  scheduler.py や crud.py はすでに datetime.now(timezone.utc) を使っており
  ファイル間で不統一。

  修正案:
    from datetime import datetime, timedelta, timezone
    expire = datetime.now(timezone.utc) + timedelta(days=ACCESS_TOKEN_EXPIRE_DAYS)

[GRN-02] config.py の USERNAME 環境変数名がOSの予約変数と衝突する可能性

  対象ファイル: config.py L69

  INIT_USERNAME = os.getenv("USERNAME", "")

  macOSおよびWindowsでは USERNAME はOS標準の環境変数（ログインユーザー名）であり、
  .env を未配置のまま開発機で起動した場合、空文字チェック（L71-74のRuntimeError）
  をすり抜けてOSのユーザー名でDBユーザーが作成される可能性がある。
  Renderではrender.yaml経由で明示的に設定されるため本番での影響なし。

  修正案: 環境変数名を INIT_USERNAME / INIT_USER_PASSWORD に変更し、
  render.yaml・.env.example も合わせて修正する。

--------------------------------------------------------------------------------

[GRN-03] NewsCard.jsx の source_url が href に未検証で入る

  対象ファイル: frontend/src/components/NewsCard.jsx L94-101

  article.source_url（RSSのlinkフィールドをそのままDBに保存した値）が
  <a href={article.source_url}> に直接レンダリングされる。
  Reactは文字列をエスケープするがhrefの javascript: スキームは
  Reactの古いバージョン（~16.8以前）では実行可能だった。
  現行のReact 18では警告のみで実際には実行されないため実害なし。
  ただしRSSソースが信頼できなくなった場合の防衛策として一応記録する。

  修正案（必須ではない）:
    const safeUrl = /^https?:\/\//i.test(article.source_url)
      ? article.source_url
      : '#';
    <a href={safeUrl} ...>

[GRN-04] CORS allow_methods=["*"] / allow_headers=["*"] が過剰に広い

  対象ファイル: main.py L35-38

  実際に使用するメソッドは GET / POST / PUT のみ。
  allow_credentials=True との組み合わせでブラウザはoriginチェックを行うため
  実害はないが、原則最小権限の観点から明示的に列挙するほうが好ましい。

  修正案:
    allow_methods=["GET", "POST", "PUT"],
    allow_headers=["Authorization", "Content-Type"],
