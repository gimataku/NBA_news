### 1-2. カバレッジ目標

**Python側・JS側をそれぞれ測り、両方が目標を満たすことを合否判定とする。**（Takumi様2026-09-01決定）

### 1-6. テストにおけるシークレットの取り扱い 🆕（v0.2新設）

**方針：テストは実際のシークレットを一切使わない（hermetic tests）。**

#### 1-6-1. 現状の問題

`tests/conftest.py` は**ダミー値を設定する前に `.env` を `override=True` で読み込んでいる**。

```python
# conftest.py L8-11
load_dotenv(os.path.join(os.path.dirname(__file__), "..", "..", ".env"), override=True)
...
# conftest.py L19-23
os.environ.setdefault("SECRET_KEY", "test-secret-key-...")   # ← 既に実値が入っているため効かない
```

`override=True` により `.env` の値が先に `os.environ` へ入るため、後続の `setdefault` は**何もしない**。結果として、**テストプロセスは実際の値で動く**。

**実値がテスト出力に現れうる経路が実在する。**

| # | 箇所 | 内容 |
|---|---|---|
| 1 | `test_auth.py` L20・L47・L61 | `json={"username": INIT_USERNAME, "password": INIT_USER_PASSWORD}` ——**実際のパスワードをリクエストボディに載せている** |
| 2 | `test_integration.py` L22 | 同上 |
| 3 | `test_routes.py` L115-121 | `from config import SECRET_KEY` を import し、**実際の鍵でトークンを署名している** |

これらのテストが**失敗すると、pytest の失敗表示・トレースバック・`--showlocals` の出力に値が現れうる**。テストの実行と出力の確認は開発支援ツールが行うため、**そのまま流出につながる**。

#### 1-6-2. 対処

| # | 対処 | 内容 |
|---|---|---|
| 1 | **`conftest.py` から `load_dotenv(...)` を削除する** | テストは `.env` を読まない |
| 2 | **ダミー値を `setdefault` ではなく無条件代入にする** | `os.environ["SECRET_KEY"] = "test-..."` の形。**開発者のシェルが実値を export していても上書きされる** |
| 3 | **サブプロセスを起動するテスト（T-P3-07）は `env` を明示的に構成する** | `os.environ.copy()` を使わず、**必要なキーだけをダミー値で組んだ辞書**を渡す。継承による混入を断つ |
| 4 | **`pytest` に `--showlocals` を付けない** | ローカル変数の一括表示は、対処1〜3を通り抜けた値を露出させる最後の経路 |

```python
# conftest.py（変更後・L6-23 相当）
# load_dotenv は使わない（テストは .env を読まない。§1-6）
import os

# ダミー値を無条件に設定する（setdefault ではない）
os.environ["ANTHROPIC_API_KEY"]   = "sk-ant-test-dummy-key"
os.environ["BALLDONTLIE_API_KEY"] = "test-dummy-key"
os.environ["SECRET_KEY"]          = "test-secret-key-for-testing-purposes-only-32chars"
os.environ["USERNAME"]            = "testuser"
os.environ["USER_PASSWORD"]       = "testpass123"
```

#### 1-6-3. 実値を必要とするテストが存在しないことの確認

**全テストが外部APIをモックしており、実際の鍵を必要とするものは1件もない。**

```
$ 各テストファイルの外部呼び出し（anthropic.Anthropic( / requests.get( の直接呼び出し）
  test_auth.py 0 / test_claude_client.py 0 / test_crud.py 0 / test_dedup.py 0
  test_filter.py 0 / test_integration.py 0 / test_routes.py 0 / test_rss.py 0
  test_scheduler.py 0 / test_score.py 0 / test_system.py 0
  → 実APIを叩くテスト：0件（すべて mocker / patch で置換）
```

| 用途 | 実値が要るか | 理由 |
|---|---|---|
| `ANTHROPIC_API_KEY`・`BALLDONTLIE_API_KEY` | ❌不要 | 外部呼び出しはすべてモック |
| `SECRET_KEY` | ❌不要 | **署名と検証が同じ鍵で行われればよい**。ダミーで完結する |
| `USERNAME`・`USER_PASSWORD` | ❌不要 | `init_user()` が作ったユーザーで `authenticate_user()` を検証する。**値が何であれ成立する** |

> **したがって対処に副作用はない。** 「テストが実値で動いていた」ことに機能上の必要はなく、**`.env` を読み込む設計自体が不要だった**。
>
> **⚠️ 本書は `.env` の内容を確認していない。** 上記はすべて `conftest.py` と各テストファイルの記述から読み取ったものであり、**ファイルの中身・値の有無には一切言及していない**。対処後も同様に、**設定はTakumi様が各環境で行い、テストはダミー値だけで完結する**。
