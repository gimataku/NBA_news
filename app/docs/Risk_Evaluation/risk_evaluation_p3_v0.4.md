### 1-4. 判断の中心：起動待ち約1分をどう見るか

**他の要素はいずれも設計で軽減されるか一度きりであるのに対し、これだけが毎回発生し、解消しない。**

| 場面 | 起こること |
|---|---|
| その日はじめて開く | **約1分待つ**（コールドスタート） |
| 15分以内に再度開く | 待たない |
| 15分以上空けて開き直す | **再び約1分待つ** |

> **本アプリの利用形態**: 個人利用・1日数回の閲覧。**開くたびに待つのではなく、「しばらくぶりに開くと待つ」**。1日2〜3回、間隔を空けて開くなら**1日あたり2〜3回の1分待ち**が発生しうる。
>
> **緩和策はない。** 定期的にアクセスして起こし続ける方法（外部からのウォームアップping）は、**750インスタンス時間/月の枠を消費し、無料枠での常時稼働は成立しない**（720時間/月＝常時稼働に近い）。加えて「スピンダウン中は時間を消費しない」という前提（リスク調査書§1-2 制約5）が崩れる。
>
> **朝の閲覧との関係**: 基本設計書§5-7 は cron を **JST 6/10/14/18/22/2時**とし「起床時には前夜の試合記事が入っている」状態を作る設計である。**バッチは GitHub Actions 側で走るため、記事は待たずに揃っている。** 待つのは**画面を開く操作**だけである。

## 2. コスト基準の再定義（リスク調査書§5-3 #10）

### 2-1. 現行基準が成立しなくなる理由

| 区分 | 現行の基準 | 前提となる「試算」 |
|---|---|---|
| 合否（要件定義書§3-1 項目6） | 月次コストが**試算の150%以内** | **$10.65/月**（Render $7.25 ＋ Claude API $3.40） |
| 中止（同§3-3-1 項目1） | 月次コストが**試算の200%**を超えた場合 | 同上 |

| # | 要望1を採用した場合に生じる問題 |
|---|---|
| 1 | 「試算」の値そのものが変わる（$10.65 は Render 前提） |
| 2 | ホスティングが$0になると、**$0に対する倍率が定義できない** |
| 3 | 残るのは Claude API のみ。**基数が小さいと倍率が過敏になる**（$1.3 の150%＝$1.95 は、記事数が2割増えただけで超える） |
| 4 | 要件定義書§3-3-1-1「合否ラインと中止ラインの関係」表の**コスト行が成立しなくなる** |

> **⚠️ 不採用の場合も「試算」の見直しが要る**（本書で新たに指摘）: 現行の試算 $10.65 は Claude API を **$3.40** と見込んでいるが、**フェーズ2の実績は $1.27〜$1.72（試算の半分以下）** である。実績合計は **$8.5〜9.0/月**であり、試算 $10.65 の 150%＝$15.98 という合否ラインは**実績のほぼ2倍**にあたる。**基準が緩すぎて機能しない。**
>
> **したがって、採否がどちらでもコスト基準は更新する必要がある。**

### 2-2. 再定義案

**方式：金額で置く**（リスク調査書§1-4-5 の推奨）

| 採否 | 想定実績 | **合否ライン** | **中止ライン** | 採否確定後 |
|---|---|---|---|---|
| **要望1を採用する場合** | 約 $1.3〜1.8/月 | **$3以内** | **$7超** | ✅**これを採用**（2026-09-08） |
| ~~要望1を不採用とする場合~~ | ~~約 $8.5〜9.0/月~~ | ~~$12以内~~ | ~~$18超~~ | ❌**破棄**（下記） |

> **✅ 決定（Takumi様2026-09-08）**: 方式は**金額で置く**。要望1を採用したため、**合否 $3以内・中止 $7超**を採る。
>
> **⚠️ 不採用側の値は残さない。** 採否が確定した以上、**有効な側だけを要件定義書に書く**。両方を残すとどちらが有効か分からなくなる。本表では取り消し線で**破棄した事実**のみを記録する（判断の経緯を追えるようにするため）。

**金額で置く根拠**

| # | 理由 |
|---|---|
| 1 | **$0に対する倍率は定義できない**（採用時のホスティング費用） |
| 2 | **基数が小さいと倍率が過敏になる**。採用時の実績 $1.3〜1.8 に対し150%は $1.95〜2.7 であり、**記事数の自然な変動で超える** |
| 3 | **判定が単純**。週次チェックリストで「今月いくらか」を見るだけで済む |
| 4 | 要件定義書§3-3-1-1 の**帯域（合否〜中止）が確保される**（採用時 $3〜7・不採用時 $12〜18） |

**各値の根拠**

| 値 | 根拠 |
|---|---|
| 採用時 合否 **$3** | 実績上限 $1.8 の**約1.7倍**。記事数が倍増しても収まる。**現行の150%という考え方と近い水準** |
