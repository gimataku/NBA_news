### 🔴 ステップ3 の罠：Neon の接続文字列はそのまま使えない

**Neon が提示する接続文字列は `postgresql://...` で始まる。これを `DATABASE_URL` にそのまま入れてはならない。**

| 形式 | SQLAlchemy が探すドライバ | 結果 |
|---|---|---|
| `postgresql://...`（Neon が提示する形） | **`psycopg2`** | 🔴**`ModuleNotFoundError: No module named 'psycopg2'`**。本プロジェクトが入れたのは **`psycopg[binary]`（psycopg 3）** である |
| **`postgresql+psycopg://...`** | **`psycopg`（3系）** | ✅正しい |

> **対処**: Neon の接続文字列の **`postgresql://` を `postgresql+psycopg://` に書き換えて**から GitHub Secrets（および後の Render 環境変数）に登録する。**それ以外（ユーザー名・パスワード・ホスト・DB名・`?sslmode=require`）は一切変えない。**
>
> **詳細設計書§3-4 は URL 例として `postgresql+psycopg://...` を示しており設計は正しい。** 本項は**運用手順として明示されていなかった点**を補うものである。
>
> 🔴**この誤りはステップ4（初回バッチ）で即座に表面化する**（GitHub Actions のジョブが `ModuleNotFoundError` で失敗）。**後戻り限界点より十分前に出るため、害は小さい。** ただし原因が分からないまま時間を使う余地があるため、先に書いておく。
